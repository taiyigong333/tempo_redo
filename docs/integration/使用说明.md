# 双服务器使用说明

## GPU-Server

- 项目根为 `/data-minio/taiyi/tempo`，分支为 `main`。
- 正式配置为 `configs/gpu_paper_chunk30_4gpu_20261114.json`。
- 环境入口为 `source env.sh`，训练入口为 `bash start_train.sh`。
- 当前状态读取 `runtime/latest_status.json`，阶段日志位于 `experiments/gpu_paper_chunk30_4gpu_20261114/logs`。
- W&B项目为 `gongcj-beijing/tempo-piperx-gpu-server`。
- ModelScope数据集为 `taiyigong3333/tempo`，前缀为 `gpu/gpu_paper_chunk30_4gpu_20261114/`。
- W&B凭据文件为 `.secrets/wandb.env`，ModelScope令牌路径由正式配置的 `modelscope.token_file` 指定。

`setup_environment.sh` 依赖已经安装的 `.tools/bin/uv`。首次部署应先从官方渠道安装uv到该目录，保留Python3.11.15及当前锁文件。配置使用国内镜像，PyAV的Linux CPython3.11 wheel有独立镜像地址。重装Transformers后重新应用 `transformers_replace` 补丁，并验证 `_temporal_attention` 存在。

发布工具使用单独的ModelScope环境。现有环境位于 `code/TEMPO/.tools/uploader`，版本为1.40.3。新机器可在项目Python准备完成后创建该环境。

```bash
cd /data-minio/taiyi/tempo/code/TEMPO
.tools/bin/uv venv --python .venv/bin/python .tools/uploader
.tools/bin/uv pip install --python .tools/uploader/bin/python modelscope==1.40.3 \
    --index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

数据集来自 `taiyigong3333/piperx_rotation_red_block` 的 `piperx_rotating_red_square_tempo.zip`。基座、分词器、SAM2权重、RGB和SAM2缓存需按现有配置准备。环境和数据验证报告位于 `docs/*verification*.json` 与 `docs/data_validation_gpu_server.json`。`start_train.sh` 会核对全量393轨迹、缓存、基座和凭据文件。

## ma800

- 项目根为 `/data/zhoushuangfan/chuanjun_gong/tempo`，分支为 `ma800`。
- 正式配置为 `configs/paper_restore_chunk30_2gpu_20261114.json`。
- 当前状态读取 `runtime/latest_status.json`。
- Python3.11.17解释器本体位于 `code/TEMPO/.venv/.python`，依赖通过uv管理。
- W&B项目为 `gongcj-beijing/tempo-piperx-ma800`，服务器专用代理配置保留在正式JSON中。
- 策略上传到 `taiyigong3333/tempo/runs/paper_restore_chunk30_2gpu_20261114/policy/`，辅助模型上传到数据集根目录 `ma800/`。
- 发布令牌默认位于 `~/.cache/tempo_modelscope/token`，发布器独立环境位于 `runtime/modelscope_uploader/.venv`。

下述命令为训练控制器入口，应在核对现有tmux、PID和阶段状态后，于服务器持久会话中运行。首次环境配置按 `code/TEMPO/docs/environment_ma800.md` 执行。

```bash
cd /data/zhoushuangfan/chuanjun_gong/tempo/code/TEMPO
.venv/bin/python -u tools/piperx/pipeline.py \
    --config ../../configs/paper_restore_chunk30_2gpu_20261114.json
```

独立发布器入口如下，辅助权重发布使用同一入口并增加 `--auxiliary-only`。

```bash
cd /data/zhoushuangfan/chuanjun_gong/tempo/code/TEMPO
../../runtime/modelscope_uploader/.venv/bin/python -u tools/piperx/upload_results.py \
    --config ../../configs/paper_restore_chunk30_2gpu_20261114.json
```

ma800 用户最新要求训练失败后由本人决定后续。正式配置为 `max_stage_attempts=1`、`recovery_requires_user_decision=true`。历史运行中的控制器曾加载旧配置，因此另部署了 `manual_recovery_guard.py` 阻止后续自动重试，源码归档于 `archive/runtime/paper_restore_chunk30_2gpu_20261114/`。新建控制器读取当前配置后最多尝试一次。

## 检查点与迁移

ma800当前格式为各rank分别保存完整优化器状态。GPU-Server格式v2将相同AdamW状态保存一次，各rank独立保存随机状态，其恢复入口兼容历史格式。恢复时保持原global batch与world size，并将模型配置、归一化、划分和decoder与对应权重配套使用。

模型部署还需匹配π0.5/TEMPO配置、u_t解码器、归一化和机器人动作变换。仓库保留现有部署入口和使用资料，真实机器人成功率与正式训练最终效果仍待评测。
