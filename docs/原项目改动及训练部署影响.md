# 原项目改动及训练部署影响

更新于2026-11-14。本文适用于 `main` 与 `ma800` 两个分支，说明当前整合版本相对官方TEMPO的改动，以及训练、检查点和部署的对应关系。

## 1. 对照范围与结论

对照基线为 `tempo-robot/TEMPO` 的提交 `dd8342a1234e7166b856ffec2d7917b51cce05e4`。本次直接读取ma800保存的该提交原始文件，并逐文件比较两个分支。官方项目根对应本仓库的 `code/TEMPO`。

当前策略使用官方π0.5/TEMPO实现，启用官方已有的时序视觉、SAM2融合、动作历史及u_t预测路径。新增工作主要覆盖PiperX数据适配、辅助模型训练入口、多卡训练、检查点、环境与发布流程。任务配置采用单臂7维动作和30帧窗口，辅助模型的参数形状及部署输入输出需与此配套。

两分支的核心模型配置、策略前向、MVAE定义、u_t解码器定义、官方策略加载器以及Transformers替换源码，均与上述基线逐字节一致。涉及的文件包括以下内容。

- `src/openpi/models/pi0_config.py`
- `src/openpi/models_pytorch/pi0_pytorch.py`
- `src/openpi/models_pytorch/gemma_pytorch.py`
- `src/openpi/models_pytorch/ut_decoder.py`
- `tools/ut/mvae.py`
- `src/openpi/policies/policy_config.py`
- `src/openpi/models_pytorch/transformers_replace/` 下的基线文件

这里的源码一致性可核验到模块定义、初始化和前向实现。训练任务的配置、数据分布、学习目标对应的标签和随机数分配仍决定实际训练结果。论文效果与机器人成功率需要正式评测。

## 2. 直接修改了哪些官方文件

下表路径均相对 `code/TEMPO`。ma800有7个基线文件内容差异，main另增加 `.python-version`，共8个。

| 文件 | 当前改动 | 对训练的影响 | 对部署和模型结构的影响 |
|---|---|---|---|
| `examples/convert_jax_model_to_pytorch.py` | 三处π0.5自适应归一化判断改用显式 `pi05` 参数 | 基座目录名为 `pi0.5_base` 等名称时，按实际模型类型选择转换分支 | 权重转换需正确指定模型类型，目标参数由官方模型定义决定 |
| `src/openpi/models/tokenizer.py` | 支持环境变量 `PALIGEMMA_TOKENIZER_PATH`，缺省沿用官方下载路径 | 可复用基座自带词表，减少训练启动的外网依赖 | 部署需提供同一词表文件，路径变化属于资源定位，词表内容影响token结果 |
| `tools/ut/train_mvae.py` | 新增 `--window`，默认16，动作维度由实际数据推断 | 支持7维数据及指定30帧窗口，归一化数组随动作维度生成 | 复用官方MVAE类，实例的动作输入输出层和时间位置参数随配置取形状，历史14维/16帧权重需匹配各自配置 |
| `tools/ut/encode_ut_windows.py` | 编码窗口与输出长度检查使用MVAE检查点的 `model.cfg.window` | u_t标签覆盖范围与已训练MVAE窗口一致 | 标签与decoder、policy的窗口需统一为30 |
| `tools/ut/train_ut_decoder.py` | 窗口读取MVAE配置，新增可选 `--delta-joint-actions` | 可按窗口起点state计算关节相对动作，随后进入policy归一化空间 | decoder的动作语义由训练选项决定，部署需配套反归一化和相对到绝对变换 |
| `pyproject.toml` | 国内镜像、PyAV固定wheel、W&B0.24.2、hydra-core与iopath，main另加入本地SAM2依赖及构建变量 | 支持服务器离线资源、视频读取与日志记录，固定依赖版本 | Linux CPython3.11的wheel地址具有平台约束，部署需安装匹配环境并应用官方Transformers补丁 |
| `uv.lock` | 保存上述依赖解析与镜像来源 | 环境版本可追溯 | 新机器按对应分支锁文件安装 |
| `.python-version`，仅main | 从 `3.11` 固定到 `3.11.15` | 固定GPU-Server解释器选择 | ma800源码标记为3.11，实际项目环境使用3.11.17，二者各有环境记录 |

`tools/ut` 中这些通用脚本属于官方入口的兼容扩展。本次正式多卡任务实际走新增的 `tools/piperx/train_aux.py` 和 `encode.py`，其参数与数据变换见后文。

## 3. 新增了哪些训练与工程能力

| 新增文件或目录 | 主要用途 | 对训练的影响 | 对部署和模型结构的影响 |
|---|---|---|---|
| `tools/piperx/prepare.py`、`prepare_gpu_server.py` | 校验轨迹、视频、时间戳和数值，生成RGB与SAM2缓存 | 减少重复视频解码和特征计算，训练依赖缓存与原始数据对应 | 缓存属于训练资源，在线部署仍需提供相同语义的图像、SAM2特征和历史输入 |
| `tools/piperx/compute_full_norm.py` 与项目根 `configs/` | 全量数据划分、30帧动作归一化与参数记录 | 正式训练覆盖393轨迹、44398帧，归一化按全量数据重算 | 每份权重需携带本次norm与动作变换约定 |
| `tools/piperx/data.py` | PiperDataset、mmap缓存、ExactBatchSampler | 复用官方变换，提供两路历史图像、动作历史与u_t标签，维持精确global batch | 固定任务prompt与相机语义，部署需构造对应输入 |
| `tools/piperx/train_aux.py`、`encode.py` | MVAE、u_t编码及decoder多卡训练 | 复用PoEMVAE、ActionDecoder、VideoLatentDecoder，支持恢复、GPU驻留数据、fused AdamW与forward编译 | decoder权重保存 `model_cfg` 与 `action_space=policy_norm`，推理按其中配置重建 |
| `tools/piperx/train.py`、`run.sh` | 原生AdamW的DDP策略训练与梯度累积 | 固定全局batch128、clip1、warmup及余弦学习率，记录loss、lr、显存和吞吐 | safetensors模块键由官方模型产生，运行所需配置需随权重提供 |
| `tools/piperx/runtime_status.py`、`pipeline.py`、`wandb_proxy.py` | 服务器持久运行、阶段顺序、资源检查与状态发布 | 按配置执行MVAE、编码、decoder、policy，处理完整检查点恢复与OOM降micro-batch | 影响作业调度与网络出口，推理加载主要使用权重、模型配置与数据变换 |
| `tools/piperx/upload_results.py`，main另有 `publish_auxiliary.py` | ModelScope分阶段发布、续传及远端校验 | 训练与上传可并行，千步里程碑可独立发布 | 发布材料包括配置、归一化、decoder和源码，需按部署位置修正路径 |
| `env.sh`、`setup_environment.sh`、`start_train.sh`，main提供 | 环境与tmux入口 | 使用项目内Python、uv环境和既有服务器资源 | 新机器需准备工具、数据、基座、SAM2权重与私有凭据 |
| `archive/runtime/`、验证工具、项目文档 | 保存实验过程、恢复守护与验证来源 | 记录当时参数和验证范围 | 历史脚本需核对当前配置接口后执行 |

策略训练对未参与前向的expert词表输出头执行 `requires_grad_(False)`，用于减少DDP无用梯度桶。该操作影响训练参数集合，适用前提为当前策略调用路径继续绕过该词表头。

辅助模型的fused优化器和forward编译属于执行后端选择，浮点舍入可能随后端变化。两卡与四卡的分批、归约顺序及随机数分配也可能产生不同训练轨迹。

## 4. 模型配置与张量形状

本任务沿用官方已有单臂u_t路径。官方 `pi05_yam_tempo_ut_ball_catch_all` 示例使用单臂7维与16帧窗口，本任务更换为PiperX数据、两路相机及30帧窗口。

| 项目 | 当前值 | 训练与部署含义 |
|---|---|---|
| 基座 | π0.5 | 使用对应JAX转换权重与词表 |
| `action_dim` | 32 | 策略动作接口与padding维度 |
| `action_history_dim` | 7 | 6个关节与1个夹爪值 |
| `predict_ut` | true | flow目标使用MVAE编码得到的u_t |
| `ut_dim` / `flow_dim` | 64 | latent预测空间 |
| `flow_positions` | 1 | 单个latent位置，由官方u_t路径定义 |
| `action_horizon` / `ut_window` | 30 / 30 | 动作chunk、MVAE窗口与decoder输出时间长度一致 |
| decoder有效输出 | `[B,30,7]` | 在policy归一化空间输出单臂动作 |
| 官方策略采样输出 | `[B,30,32]` | `_decode_ut` 将7维动作padding到32维，机器人输出变换取有效7维 |
| 视觉历史 | 3帧 | 当前帧及此前10、20帧，数据按30Hz处理 |
| SAM2特征 | 64个256维token | 当前头部相机的8×8特征 |
| 动作历史 | 10个7维桶 | 对过去300帧按每30帧均值聚合 |
| 辅助模型 | `MVAEConfig(window=30, action_dim=7, sam_grid=1, latent_dim=64, beta=0)` | MVAE与decoder均以该配置实例化 |

MVAE与decoder的时间位置参数、动作输入输出投影依赖window和action_dim。复用官方类仍需满足检查点参数形状兼容，30帧/7维辅助权重应搭配其自身 `model_cfg`。π0.5基座用于初始化TEMPO时，新增任务分支及latent投影按官方类与当前配置初始化，训练器显式处理基座参数形状差异。

当前SAM2融合沿用官方零gate与零输出投影初始化。历史记录中的非零gate梯度来自早期初始化实验，当前复现版本以官方初始化为准。

## 5. 训练目标、数据和评测的影响

1. 正式训练使用全部393轨迹，验证轨迹数为0。辅助模型在当前配置下按训练loss选择best，policy的 `eval_interval=0`。训练loss、辅助重建误差和真实机器人成功率需要分别报告。
2. policy标签先对6个关节减去当前窗口起点state，夹爪沿用绝对开口，再执行本次分位归一化。MVAE动作分支使用自身训练统计，decoder专门学习policy归一化空间，配套加载依赖其保存的统计与模型配置。
3. 数据输入复用YamInputs、DeltaActions、Normalize、TokenizePrompt与PadStatesAndActions，任务prompt为 `grab the rotating red square`。相机输入为head与left_wrist，缺失历史与窗口尾部按现有padding语义处理。
4. policy使用原生 `torch.optim.AdamW`、官方参数混合精度及BF16 autocast。学习率5e-5降至5e-6，warmup500、计划5000次更新、global batch128。
5. ma800为micro32、累积2、两卡，GPU-Server为micro32、累积1、四卡。相同global batch约束训练样本权重，浮点归约与随机数顺序受执行配置影响。
6. ma800恢复官方策略时复用了此前完成的MVAE、u_t与decoder。其来源见该分支正式配置的 `restoration.reuse_auxiliary_from`。GPU-Server有自己的辅助训练流程与W&B记录，跨服务器使用时应核对对应来源。

## 6. 检查点格式与恢复影响

| 项目 | ma800 | main / GPU-Server |
|---|---|---|
| 模型文件 | `model.safetensors` | `model.safetensors` |
| 优化器状态 | 各 `rank_N.pt` 保存完整AdamW状态 | 格式v2，仅 `rank_0.pt` 保存一份共享AdamW状态 |
| 随机状态 | 每rank独立保存 | 每rank独立保存 |
| 恢复入口 | 原逐rank状态读取 | 同时兼容逐rank旧格式与共享格式 |
| 当前rank数量 | 2 | 4 |
| 滚动快照 | 每100step | 每100step |
| 保留里程碑与发布 | 每1000step及最终step | 每1000step及最终step |

两端恢复训练均核对global batch与world size。跨rank数量迁移涉及数据分配和随机状态重新对应，现有训练恢复接口要求匹配原world size。仅加载模型用于推理时，优化器与逐rank随机状态属于训练恢复材料。

保存流程先写临时目录，所有rank完成后发布正式目录与latest指针，再清理旧滚动快照。GPU-Server的去重依赖标准DDP各rank具有相同AdamW状态这一前提。

## 7. 部署需要配套哪些材料

官方 `create_trained_policy` 使用调用方传入的 `train_config` 构建模型，并通过 `model.safetensors` 识别PyTorch权重。当前训练目录中的 `model_config.json` 用于记录配置，部署调用方需将这些值落实到实际 `train_config`。

建议按以下依赖顺序核对部署材料。

1. 使用包含官方Transformers时序注意力补丁的匹配环境，加载π0.5/TEMPO配置与对应词表。
2. 配置u_t预测、64维latent、30帧窗口、7维动作历史和相应视觉/SAM2参数，提供匹配的 `ut_decoder_path`。
3. 同时取得policy权重与30帧/7维decoder权重。单独运行u_t到动作推理时需要decoder，MVAE用于训练和重新生成标签，按使用目标保存其权重与统计。
4. 显式向 `create_trained_policy` 传入本次 `norm_stats`，或将统计整理到官方默认的 `checkpoint/assets/<asset_id>` 布局。当前step目录直接保存的 `norm_stats.json` 需要这一步对接。
5. 复现head/left_wrist图像、三帧历史、SAM2特征、动作历史、state及prompt。训练使用预计算缓存，在线服务需提供对应特征生成与历史维护链路。
6. 输出端执行匹配的Unnormalize和AbsoluteActions，对6个关节恢复绝对动作，保留夹爪语义，将有效7维动作接入PiperX执行接口。
7. 将decoder、词表、资源、统计及模型配置里的服务器绝对路径改为部署机器实际位置，再验证正式权重加载、有限输出、动作形状与真实任务表现。

数据变换的前6维、30帧窗口、有效7维动作和归一化统计均属于部署契约。保留官方模型加载器仍需要上述配置与资源对接。

## 8. 历史实验与当前采用状态

| 历史尝试 | 当前状态及影响 |
|---|---|
| SAM2输出投影改为随机初始化，让零gate获得梯度 | 当前两分支核心模型已恢复官方双零初始化，早期实验权重来源需另行核对 |
| 自定义GPUAdamW、FP32主权重与动量分片 | `optimizer.py`保留实验实现，当前正式 `train.py` 调用原生AdamW |
| prefix压缩、额外模型配置开关与外层重算修改 | 当前核心配置和前向均采用官方基线，旧开关只出现在部分历史工具中 |
| GPU-Server关闭外层重算 | 真实batch1前向、830个梯度张量和随机状态对照一致，batch32两次OOM，正式配置使用当前重算策略 |
| policy micro64候选 | 历史候选记录保留，当前正式配置为micro32 |

旧 `verify.py` 的非零gate梯度断言对应早期初始化实验。`verify_execution.py` 与 `evaluate.py` 的独立命令入口仍引用已移除的 `compact_prefix` 或 `checkpoint_joint_forward` 字段，直接运行存在配置异常。`train.py`仅导入 `evaluate_flow` 函数，当前正式配置关闭policy验证。后续使用这些独立工具前，需要按当前接口修正并验证。
