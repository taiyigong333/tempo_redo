# PiperX TEMPO 三卡训练方案

日期为2026-11-14。本文件记录三卡阶段方案，当前正式执行依据同目录《两卡全量训练执行方案.md》与configs/formal_chunk30_2gpu_20261114.json。

## 目标、输入与输出

使用ma800本地π0.5基座，对旋转红色方块数据进行完整TEMPO微调。预测30帧、每帧7维动作，训练与验证由W&B在线记录。

数据来自 `/data/zhoushuangfan/chuanjun_gong/tempo/data/data11_7/piperx_rotating_red_square_tempo.zip`，已解压为同级 `piperx_rotating_red_square/`。实际验证393条轨迹、44398帧、786个视频、30Hz、head/left_wrist两路224×224图像。action[t]等于state[t+1]，全量最大误差0。

原始基座为 `/data/zhoushuangfan/chuanjun_gong/base_model/pi0.5_base`。PyTorch转换权重位于项目 `caches/pi05_base_pytorch/model.safetensors`。策略训练直接从该基座初始化，新增TEMPO模块与u_t头随本次实验学习。

## 数据与评测

本次采用官方默认的按轨迹80/20划分，split seed为0，314条训练轨迹、79条验证轨迹。这个划分是本次采用的默认方案，提交用户确认。归一化只拟合训练集，六个关节按每个窗口当前实测state相对化，夹爪为绝对值。预测窗口、MVAE窗口和decoder窗口统一30帧。

策略每500次更新及末步评估固定抽样的128个验证帧，flow MSE按完整u_t窗口计数。辅助模型每轮评估全部验证窗口并保存best/last。任务成功率需在正式训练后的离线与真机评测中取得。

## 正式参数

| 项目 | 建议值 |
| --- | --- |
| 硬件 | ma800三张A800 80GB，共享显存条件 |
| 模型 | π0.5 + TEMPO-MOT + TEMPO-ACT + u_t，全量微调 |
| 预测chunk | 30帧，原生动作维度7 |
| 视觉历史 | 3帧，间隔约0.333秒 |
| 动作历史 | 10桶、10秒、30Hz |
| SAM2 | 官方SAM2.1 tiny，冻结特征预计算 |
| u_t维度 | 64 |
| 策略全局有效batch | 128 |
| 单卡micro-batch | 最大4 |
| 梯度累积 | 每次更新11个micro，三卡样本43/43/42，尾批按样本数加权 |
| 策略更新数 | 5000 |
| 学习率 | warmup500次，5e-5峰值，余弦衰减到5e-6 |
| AdamW | betas=(0.9,0.95)，eps=1e-8，weight_decay=1e-10 |
| 梯度裁剪 | 1.0 |
| 数值精度 | BF16计算，FP32主权重和FP32动量按rank分片，训练状态驻GPU |
| 执行优化 | 内部逐层重算，关闭外层重复重算，compact_prefix=false |
| EMA | 关闭，与项目PyTorch训练入口一致 |
| 随机种子 | 42 |
| checkpoint | 每1000次及最终5000次更新保存完整状态，原子更新latest.json |
| W&B | gongcj-beijing / tempo-piperx-ma800，online |

策略5000步、batch128、warmup500、学习率和AdamW参数来自项目TEMPO配置。三卡分片、梯度累积与GPU上的FP32主权重用于适配当前硬件和共享显存。30帧来自用户本次要求。

MVAE采用官方示例的latent64、beta0、pool-spatial、hidden512、2层encoder/decoder、8头，global batch64、lr1e-4、weight_decay1e-4、余弦调度100轮、clip1。decoder同样global batch64、lr1e-4、weight_decay1e-4、余弦调度80轮、clip1。两者均三卡运行，64个全局样本按22/21/21加权。

## 时间估算

所有策略测量均发生在其他用户任务约40GB/卡占用期间。

| 方案 | 稳态秒/更新 | 单卡峰值分配显存 |
| --- | --- | --- |
| micro1、累积43 | 41.9503 | 约28.11GiB |
| micro2、累积22 | 34.6528 | 约28.11GiB |
| micro4、累积11、关闭外层重复重算 | 29.4196 | 约31.05GiB |

推荐方案相对micro1短测稳态加快约29.9%。5000次策略更新估算40.86小时。完整checkpoint约44GB，实测保存31.65秒，5次约2.6分钟。MVAE100轮与decoder80轮依据有限步吞吐估计额外1～2小时，编码约半分钟。SAM2全量预计算与基座转换已经完成。

当前共享负载下，完整训练预算建议约42～50小时。估算来自短程测量，共享任务的计算和显存负载会影响实际总时长。

## 短测结果与边界

数据验证、三卡MVAE和decoder更新、三卡编码、策略更新、完整保存恢复、GPU分片AdamW参考一致性及有效全局batch128均已验证。执行优化关闭外层重复重算后，真实样本loss差0，830个梯度张量差0。联合前缀压缩试验梯度相对L2差2.98%，对应开关在推荐配置中为false。

短测使用有限步辅助模型与标签，相关产物带test_only。正式MVAE、decoder、标签与策略将在用户确认后于独立目录生成。短测loss用于核验数据流与梯度，正式任务精度由后续实验评测。

W&B目前使用用户授权的临时代理 `http://127.0.0.1:17891`，其上游为本地代理通道。后续执行前检查代理可达性。凭据由服务器W&B认证文件读取。

## 确认后的执行顺序

以下命令用于用户确认后的执行设计。

```bash
cd /data/zhoushuangfan/chuanjun_gong/tempo/code/TEMPO
export WANDB_PROXY=http://127.0.0.1:17891
P=/data/zhoushuangfan/chuanjun_gong/tempo
R=$P/experiments/formal_chunk30_v1
bash tools/piperx/run.sh mvae --output "$R/mvae"
bash tools/piperx/run.sh encode --mvae "$R/mvae/best.pt" --output "$R/ut"
bash tools/piperx/run.sh decoder --ut-dir "$R/ut" --output "$R/decoder"
bash tools/piperx/run.sh policy --mode formal --ut-dir "$R/ut" \
  --decoder "$R/decoder/best.pt" --output "$R/policy" \
  --steps 5000 --batch 128 --micro-batch 4 --workers 2 \
  --disable-joint-checkpoint --save-interval 1000 \
  --eval-interval 500 --eval-samples 128
```
